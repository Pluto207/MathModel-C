## 它解决什么问题

Mrite 把数模工作拆成四层：

1. Skill/：面向 Claude Code 的执行规范，约束读题、计划、逐题编程、论文生成和编译。
2. 模板/：LaTeX 论文样式、章节拆分、思源宋体字体和主文件结构。
3. 算法/：按优化、预测、分类、评价分类的算法目录。
4. 示例输入：题目 PDF、CSV、求解计划和一份已编译论文。

它的核心思想是“先计划，再逐题求解；代码先算后画；论文模块化；编译后检查日志”。这套思想适合作为本工作区的骨架。

## 已采用的部分

- 使用 题目/ 数据/ 求解/ 论文/ 四区结构。
- 每个问题单独保存 Python、图片和结果。
- 使用 求解/求解计划.md 记录方法、输出、依赖与异常预案。
- 论文按摘要、引言、总体分析、假设、符号、建模求解、检验、评价、推广、参考文献、附录拆分。
- Python 默认使用 pandas、NumPy、SciPy、scikit-learn、matplotlib；绘图不依赖 seaborn。
- LaTeX 默认使用 XeLaTeX，并保留中文字体与 format.cls。

## 本地修正

上游 CLAUDE.md 强调全自动、不询问。对于真实竞赛，这一条需要改成“自动推进 + 关键节点复核”：

- AI 不能替队员确认题意、数据含义、物理单位或最终结论。
- AI 生成的模型必须先有可运行基线和验证结果，才进入论文。
- “每题至少 4—6 张图”不是硬指标；无结论价值的图会增加论文负担，应按论证需要取舍。
- “只用 matplotlib”可以作为默认以减少依赖，但若赛事环境允许，其他库也可用于计算；最终以可复现和稳定为准。
- “摘要严格一页、参考文献 8—15 条、优点 4 条缺点 2 条”等属于模板建议，若赛事官方格式另有要求，以官方要求为准。
- 上游 README 中出现过 Mrite-Skills 与当前仓库地址不一致的旧命名，本地以实际拉取的 Mrite 为准。

## 推荐使用方式

每道新题复制 竞赛项目模板/，先把题目和数据放入对应目录，然后由队伍共同维护计划文件。AI 的请求建议写成：

“读取题目和数据，先完成数据审计与求解计划；对每问给出可解释基线、备选模型、验证方案和输出文件名。未经我确认不要把未经验证的结论写入论文。代码、CSV、图片和 LaTeX 均保存到对应目录，并在结束时报告运行命令、指标和未解决风险。”

## 不应做的事

- 不直接复制示例论文中的数字、结论或参考文献。
- 不把算法库中的空目录当成已经实现的算法。
- 不在没有验证集、基线或约束检查时宣称模型有效。
- 不把自动编译成功等同于数学正确。
