# 全国大学生数学建模竞赛工作流

## 0. 总体节奏

目标不是“把所有方法都试一遍”，而是在有限时间内形成一条可复现的证据链：题意理解 → 数据审计 → 模型假设 → 基线结果 → 改进模型 → 验证与敏感性 → 论文表达 → 编译交付。

建议三人分工，但所有人共享同一份 求解/求解计划.md：

| 角色 | 主要职责 | 必须交付 |
|---|---|---|
| 建模负责人 | 题目拆解、假设、模型结构、方法取舍 | 模型草图、符号表、假设清单 |
| 算法/数据负责人 | 数据审计、预处理、代码、实验、图表 | 可运行脚本、结果 CSV、图表、日志 |
| 论文/验证负责人 | 论文组织、引用、交叉核对、编译排版 | LaTeX、检查报告、最终 PDF |

分工不等于隔离：每个关键结论至少由另一名队员复核。

## 1. 赛前几天

### 环境冻结

- 安装 Python 3.10+、NumPy、pandas、SciPy、scikit-learn、matplotlib、openpyxl、PyPDF2、python-docx。
- 安装 XeLaTeX；验证 xelatex --version。
- 运行一个最小 Python 脚本和一个最小 LaTeX 文档，确认中文字体、图片、表格均可用。
- 熟悉 竞赛项目模板/ 的目录，不在比赛时临时决定文件命名。

### 训练闭环

至少完成一套历年题，严格走完：读题、计划、数据审计、基线、改进、检验、论文、编译。训练重点是时间盒和复盘，不是追求每题最复杂的模型。

## 2. 比赛开始后的时间盒

时间因题目和队伍速度调整，下面是默认节奏。

### 阶段 A：读题与选题

1. 三人独立通读题目，分别写出每问的“输入—输出—约束—评价指标”。
2. 汇总为问题依赖图，标记哪些问题必须共享前问结果。
3. 对每个候选题快速判断：数据是否可读、核心方法是否熟悉、结果是否能验证、论文是否能讲清楚。
4. 选定一题后冻结方向；若出现致命数据问题或不可验证，立即按预案切换，不在局部死磕。

### 阶段 B：数据审计与建模计划

在写任何模型前完成：

- 文件、Sheet、行列数、字段含义、单位、时间范围记录。
- 缺失值、重复行、异常值、量纲不一致、多级表头、备注行记录。
- 明确训练/验证划分，防止时间泄漏和目标泄漏。
- 为每问写主方法、基线方法、失败替代方法和预期输出。
- 在 求解计划.md 中写出依赖顺序和预计耗时。

### 阶段 C：先做可解释基线

每问先实现一个能跑通、能解释、能验证的基线：

- 预测：均值/季节性基线、线性回归、ARIMA 等。
- 分类：多数类、逻辑回归、决策树等。
- 评价：标准化 + 熵权/TOPSIS 等。
- 优化：线性/整数规划或贪心基线，再考虑遗传算法、模拟退火等。
- 机理题：先写变量关系和边界条件，再数值求解。

复杂模型只有在指标、稳定性或解释性上带来明确收益时才保留。

### 阶段 D：实验与结果锁定

每次实验记录：数据版本、随机种子、参数、运行命令、指标、输出文件。结果文件必须落在对应问题的 结果/ 目录，图落在 图片/ 目录。不要只把数字留在终端或聊天记录里。

最低验证要求：

- 预测/分类：留出集或交叉验证，报告至少两个互补指标。
- 优化：可行性检查、约束违背检查、与基线比较，必要时多随机种子重复。
- 评价：权重敏感性、排序稳定性、指标方向性检查。
- 机理：量纲/边界条件/极端情形/参数敏感性检查。

### 阶段 E：论文写作

推荐顺序：

1. 先写符号、假设、问题重述和总体分析。
2. 按问题写“分析与准备”和“建模与求解”。模型建立和求解放在同一问题文件，保持符号一致。
3. 写模型检验，再写模型评价、改进推广和摘要。
4. 最后补齐参考文献与附录，删除未引用文献和无来源数字。

每个问题的正文必须回答四件事：为什么这样建模、公式是什么、如何求解、结果说明什么。

## 3. 论文验收门

### 内容门

- 摘要不超过模板约束，包含问题、方法、核心结果和结论。
- 每个问题均有明确输入、输出、变量、假设、模型、求解和验证。
- 优化模型写全决策变量、目标函数和约束；预测模型写出训练/验证策略；评价模型写清指标方向和权重方法。
- 图表均有编号、标题、单位、正文引用，且不展示无法解释的装饰性图。
- 参考文献与正文引用一一对应；不保留模板示例文献。

### 数据门

- 论文数字可由 求解/问题X/结果/ 中的 CSV 或代码复算。
- 代码从项目相对路径读取数据，不依赖个人电脑绝对路径。
- 随机过程固定种子或报告重复实验范围。
- 预处理没有使用未来信息；缺失和异常处理有记录。

### 工程门

- xelatex 至少运行两遍，日志无 Error。
- 检查 Overfull/Underfull/Float too large，并人工查看 PDF。
- 论文目录、图片、公式、中文字体和页码正常。
- 最终只提交竞赛要求的文件，不提交中间缓存和无关大文件。

## 4. 常见失败与切换规则

- 数据读不进来：先保存原始副本，检查编码、Sheet、合并单元格和备注行；必要时写一次性转换脚本。
- 模型不收敛：检查尺度、初值、约束和目标函数；先退回基线，再替换求解器或降低模型复杂度。
- 指标很好但不可解释：保留为对照实验，不作为唯一主模型；补充可解释模型或特征贡献分析。
- 结果与常识冲突：优先回溯数据清洗、单位和目标方向，不要用文字强行解释。
- 论文写不完：先保证每问形成“模型—结果—验证”闭环，再扩展背景和排版。

## 5. 交卷前 30 分钟

冻结代码和数据版本，重新运行关键脚本，确认输出时间和文件齐全；编译论文两遍并运行检查脚本；两名队员分别从 PDF 和结果 CSV 反向核对关键数字；按赛事要求重命名最终文件并打开最终 PDF 检查首页、目录、摘要、最后一页和图表页。
