# 结构模块升级方案（数模C）

## 现有问题
通用模板容易按固定章节或算法名称生成论文，导致问题依赖不清、图表与论点脱节、假设和检验分离。

## 重构后的中间表示
在生成论文前先建立四张内部表：

1. `问题依赖图`：Q1…Qn 的输入、输出、继承变量和新增约束；
2. `模型合同表`：每问的假设、方程、目标、约束、算法和验证；
3. `主张—证据表`：正文主张与代码、结果、图表、来源；
4. `图表契约表`：每图要证明的主张、数据源、统计口径和正文位置。

## 框架生成算法

```text
读取题面与附件
→ 识别子问题和依赖
→ 判断每问模型族
→ 生成基线—主模型—检验链
→ 安排前问到后问的交接段
→ 为每个主张分配证据
→ 为每个证据主张分配图表
→ 生成中文国赛章节
```

## 逻辑校验规则

- Q2/Q3 使用前问结果时，正文必须写明继承关系；
- 新增变量/约束必须能找到模型或代码落点；
- 每个关键假设至少连接一个模型组件和一个检验/边界；
- 每个核心数字必须连接结果文件；
- 每张正式图必须连接主张和正文段落；
- 摘要数字必须是正文/结果中的子集；
- 评价与推广不能新增未经正文验证的结论；
- 模型版本变化后，相关主张状态自动退回 REVIEW。

## 对 C 的实现建议

保留 A 的 `论文/论文.tex` 唯一出口，增加 B 风格的内部证据表和逻辑门；比赛模式只强制四门 M/R/E/W，训练模式再启用详细门禁。
