# 数模 C — 多机 × 异构 Agent 协同方案（线下集中版）

> 适用：三人坐在一起比赛（线下集中），但各用各的电脑、各用各的 AI agent（OpenClaw / Claude Code / Codex / 其他）。
> 核心原则：**Skill 每机各装；比赛项目只有一份，放在主工作区机共享，三台电脑读写同一份文件。** 赛题数据绝不进入 GitHub 或任何网络服务。

---

## 一、总体架构

```text
┌─ GitHub：MathModel-C（Public）─────────────┐
│  Skill 方法库 + 模板 + 工具（无赛题数据）      │
└────────────────────────────────────────────┘
        │ 各机 clone（只装一次）
        ▼
┌─────────────┬─────────────┬─────────────┐
│ 电脑A（主工作区） │ 电脑B         │ 电脑C         │
│ agent: OpenClaw │ agent: Claude │ agent: 其他   │
│ Code           │              │              │
└──────┬──────────────┬─────────────┘
       │  SMB 局域网共享（读写同一目录）
       ▼
┌────────────────────────────────────────────┐
│ \\电脑A\mathmodel2026  （唯一权威项目目录）      │
│   题目/ 数据/ 求解/ 结果/ 图表/ 论文/ state/    │
└────────────────────────────────────────────┘
```

- 只有一台电脑需要装完整 MATLAB + XeLaTeX 工具链？不——谁负责跑代码，谁的电脑就要有 MATLAB；谁写论文，谁的电脑就要有 XeLaTeX。
- **主工作区机建议**：MATLAB + XeLaTeX 都齐、且跑得动的那台（通常就是队长/编程主）。

---

## 二、落地步骤（Windows 局域网，约 10 分钟）

### 第 1 步：主工作区机（电脑A）建共享目录

1. 新建目录，例如 `D:\mathmodel2026`（或桌面/工作区任意位置）。
2. 右键该目录 → 属性 → **共享** → 共享给"Everyone"，权限设为**读取/写入**（只对内网）。
3. 记下网络路径：`\\电脑A的IP或主机名\mathmodel2026`。
4. 查看 IP：`ipconfig` → IPv4 地址（三台要在同一局域网/Wi-Fi）。

> 安全提示：共享只开在可信局域网；比完赛记得取消共享。不要对公网开放。

### 第 2 步：电脑B、电脑C 连接共享

Windows 资源管理器地址栏输入：

```text
\\电脑A的IP\mathmodel2026
```

右键 → **映射网络驱动器** → 选盘符（如 `Z:`）。以后三台电脑都指向 `Z:\` 里的同一份项目文件。

macOS/Linux 队员：`Finder → 前往 → 连接服务器`（`smb://IP/mathmodel2026`）或 `mount -t cifs`。

### 第 3 步：三台电脑各自初始化 Skill（只做一次）

每台电脑都从 GitHub 拉取方法库并安装到自己的 agent：

```bash
git clone https://github.com/Pluto207/MathModel-C.git
cd MathModel-C
python tools/fonts/fetch_sourcehan.py   # 每台都要（LaTeX 编译用）
python tools/fonts/setup_fonts.py       # Windows 电脑各跑一次
python tools/c.py self-check            # 期望 PASS
```

各自 agent 安装（三者互不影响）：
- OpenClaw：仓库放工作区，按技能安装方式注册
- Claude Code：`~/.claude/skills/mathmodel-c/`
- Codex：`~/.codex/skills/mathmodel-c/`
- 其他工具：参照各自 skills 目录

### 第 4 步：在主共享目录里初始化赛题项目（只做一次，队长执行）

```bash
cd Z:\mathmodel2026        # 或 \\电脑A\mathmodel2026
python <MathModel-C路径>/tools/c.py init 2026国赛-A题 --questions 4
```

此后**所有**代码、结果、图表、论文都在共享目录里，三台电脑看到的是同一份。

## 三、多 Agent 写锁纪律（关键！）

三个 agent 可以**同时读**同一份文件，但**同一时刻只能有一个写**同一个文件/目录。按角色切分写入区，物理上避免冲突：

| 写入区 | 谁写 | 谁读 |
|---|---|---|
| `求解/问题1/` | 编程主 | 全队 |
| `求解/问题2/` | 建模主（或副编程） | 全队 |
| `结果/`、`图表/` | 对应问题负责人 | 全队 |
| `论文/*.tex` | **同一时刻只有论文主一人写** | 全队读 |
| `state/decision_log.json` | 队长/当前阶段负责人 | 全队 |
| `AI使用台账.json` | 谁用了 AI 谁追加 | 全队 |

硬规则：
1. **谁写谁负责**：写完立即保存，其他人不覆盖未确认版本；
2. **论文是单写者**：任何人不直接改论文主的 `.tex`，发现问题口头/群里告诉他改；
3. **AI 写入边界**：每个 agent 的 prompt 里明确"只允许写 `Z:\...\求解\问题X`，禁止写论文和 state"；
4. 改模型/参数/结果后，让论文主运行一次 `version` 检查（manifest 变化会自动把相关主张打回 REVIEW）；
5. 每天/每半天结束时，队长把 `state/` 与 `AI使用台账.json` 各机核对一致（共享目录下本来就只有一份，无需合并）。

> 因为用的是共享目录而非 git 同步，**不存在"合并冲突"**；代价是"写锁纪律"必须靠人遵守。多人同时改同一个文件 = 覆盖，这是唯一的风险点。

## 四、Agent 项目路径约定（写进各自 Prompt）

三个 agent 的项目根目录都是同一个共享路径，例如：

```text
Windows 电脑B/C：Z:\mathmodel2026\2026国赛-A题
Windows 电脑A：  D:\mathmodel2026\2026国赛-A题
macOS/Linux：    /Volumes/mathmodel2026/2026国赛-A题
```

给 agent 的 prompt 里第一句就写死：

```text
项目唯一权威目录：Z:\mathmodel2026\2026国赛-A题（三台电脑共享同一份，禁止在本地另建副本）。
你只负责写入：求解/问题X、结果/、图表/。禁止写入：论文/、state/（除非你是论文主/队长）。
开始前先确认该目录存在且可写。
```

## 五、备选：Syncthing（不想开 SMB 共享时）

SMB 映射是最简单的；若网络/权限折腾，可用 Syncthing（局域网 P2P 实时同步，**不走互联网**，合规）：

1. 三台都装 Syncthing（syncthing.net）；
2. 电脑A 添加文件夹 `D:\mathmodel2026`，共享给电脑B/C；
3. 电脑B/C 接受，选同样目录名（如也放 `D:\mathmodel2026`）；
4. 三台实时双向同步。注意：**同一文件同时被两人改会产生冲突副本**，所以上面的"写锁纪律"依然适用，且建议开启"忽略删除"防误删。

---

## 六、红线提醒

- ❌ 赛题 PDF、附件数据、结果 CSV **不放进 GitHub**（公开或私有都不行）——只存在于局域网共享/本机。
- ❌ 不把赛题内容发给任何外部 AI 或服务（遵守当届竞赛纪律）。
- ✅ GitHub 仓库只放 Skill 方法库、模板、工具、文档。
- ✅ 队内三人 + 三个 agent 通过共享目录协作完全合规（队内讨论与协作是允许的）。
