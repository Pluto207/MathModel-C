# A 初稿 → C 优化 → 最终整合流程

> 适用于三人、三台电脑、异构 Agent、比赛期间可能分开的 CUMCM 队伍。

## 1. 双阶段原则

```text
数模A：快速形成完整初稿，建立共同讨论对象
        ↓ 初稿冻结
数模C：逐问复核、MATLAB重做、证据绑定、论文重写
        ↓ C版本冻结
最终整合：只保留 C-approved 版本作为交卷依据
```

A 的输出全部视为 `DRAFT`，不得因为已经编译或有数值就自动进入终稿。C 不是简单润色器：凡涉及核心假设、目标函数、约束、关键数字和模型有效性的内容，必须重新审核，必要时重新建模和运行。

## 2. 阶段一：A 快速初稿

项目中单独保留：

```text
00_A初稿/
├── 题目/
├── 数据/
├── 求解/
├── 结果/
├── 图表/
└── 论文/
```

A 阶段目标：在时间盒内形成每问都有初步模型、代码、结果和论文位置的完整草稿；不要在某一问无限追求最优。

初稿冻结记录至少包含：题目理解、每问模型、关键假设、算法、结果、已知问题、待 C 重做项、生成时间和使用工具。

## 3. 阶段二：C 按角色重做

### 建模主

读取 A 初稿，但重新填写各问 `模型合同.md`，建立：

```text
假设 → 方程/约束 → 验证 → 适用边界
```

审查变量、单位、目标方向、约束和前后问继承关系。未经 `APPROVED` 的模型合同不能交给 MATLAB 主做正式全量结果。

### MATLAB 主

将 A 代码和结果视为未经验证的基线候选。读取已批准模型合同，先实现 C 基线和最小切片，再用 MATLAB 重跑主模型、约束、敏感性和图表。所有最终数字来自 MATLAB 结果包和 manifest，不沿用 A 论文中的手工数字。

### 论文主

保留 A 初稿作为结构参考，建立 C 的主张—证据表和图表契约。结果锁定后重写模型解释、结果分析、摘要和评价；没有结果文件支撑的数字标记 `MISSING_EVIDENCE`，不得进入终稿。

## 4. C 版本冻结条件

只有同时满足以下条件，才把 C 版本作为交卷候选：

- 每问模型合同已由建模主和 MATLAB 主确认；
- MATLAB 最小运行和正式运行有命令、版本、种子与输出；
- 关键约束、单位、边界和敏感性已检查；
- 关键主张均有代码、结果、图表或可追溯来源；
- 摘要数字由两名队员反查；
- 论文主稿通过 CUMCM 终审清单；
- AI 使用台账和支撑材料完成。

最终只认：

```text
C-approved-model
C-approved-result
C-approved-paper
```

## 5. 失败回退

C 重做失败时，回到最近一个可复现版本，不把 A 结果强行写成最终结果。若 A 与 C 的模型语义不同，保留差异说明，由建模主裁决；若结果不同，论文主必须等待 C 结果确认。
